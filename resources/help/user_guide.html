{{const:APP_NAME}} user guide

For version {{const:APP_VERSION}}. Press {{key:user_guide}} in {{const:APP_NAME}} to open this page at any time.

What it does

{{const:APP_NAME}} shows what a device sends over a serial port, line by line, with the time each line arrived. It can write those lines to a log file, plot the numbers in them, send commands back, and do all of this for several devices at once, each in its own tab.

  • Lines are recorded as they arrive, whether or not the screen keeps up with a fast device.
  • Logs are plain text files that any editor opens. A spreadsheet file can be written beside them.
  • What your devices send never leaves your computer. See Privacy.

The tour

The tour shows each part of {{const:APP_NAME}} in turn: it rings one control, says what it does, and goes on when you choose Next. It is offered once, at the first start of a version that has it, and Help > Take the tour... opens it at any time.

  • Chapters. Take the whole tour, or any chapter on its own: connecting a board, reading the console, logs and exports, sending commands, the plot, watching the board, alerts and highlights, and settings, updates and help. The list says which chapters you have taken.
  • No board needed. From the second chapter on, the tour opens a tab called Sample, which reads a sample board built into {{const:APP_NAME}}. It opens no port, is not saved, and is closed when the tour ends. Your own tabs stay as they are.
  • It takes you there. A step about an entry of a menu opens that menu with the entry chosen; a step about a setting opens Preferences at its page. Nothing can be changed while the tour is shown, and Preferences opened by the tour closes without saving.
  • Keys. Enter or the right arrow goes on, the left arrow goes back, and Esc closes the tour.

After a later update that adds something new, a chapter of just what is new is offered instead, and it stays in the Help menu, named for its version.

Connect a device

A new tab opens on the list of serial ports. The list updates by itself: plug a device in and it appears, marked New.

  1. Choose the port. Double-click it, or select it and press Enter, to connect at once.
  2. Check the baud rate. The list offers {{const:BAUD_RATES}}; you can also type any whole number from {{count:BAUD_RATE_MIN}} to {{count:BAUD_RATE_MAX}}. It must match the rate the device uses.
  3. Choose Connect.

Most devices use 8 data bits, no parity and 1 stop bit (8N1), with no flow control, and that is where every port starts. The button beside the baud rate shows the port's settings; choose it to change them. See Port settings.

A port you have used before is offered the baud rate it last used. A port used for the first time is offered {{const:DEFAULT_BAUD_RATE}}, or the rate you set in Preferences.

If the port does not appear, press {{key:refresh_ports}} and see Troubleshooting.

Port settings

The button beside the baud rate, for example 8N1, opens the settings of the chosen port. They are remembered for that port and used each time it is connected.

SettingWhat it does
Data bits5, 6, 7 or 8 bits in each character.
ParityNone, Even or Odd; Mark and Space on Windows and Linux.
Stop bits1 or 2; 1.5 on Windows.
Flow controlNone, Hardware (RTS/CTS) or Software (XON/XOFF).
DTR at open, RTS at openWhether each line is set on as soon as the port opens. Many boards reset when DTR or RTS changes. With hardware flow control the driver sets RTS.

Usual settings returns to 8N1 with no flow control and both lines on. The settings cannot change while the port is open: disconnect first. A choice the device or its driver refuses is reported as the reason the port could not be opened.

While connected, Lines in the toolbar sets DTR and RTS, sends a break of {{const:BREAK_DURATION_MS}} ms, and shows the input lines. Each change you make is noted in the session as a line of {{const:APP_NAME}}'s own. The status bar shows the input lines CTS, DSR, DCD and RI: a line that is on is drawn brighter, one that is off is dimmed.

Start a log

The console shows the data; a log keeps it. Choose Start log or press {{key:start_log}}.

Give the log a name, or leave the field empty to use "{{const:FILENAME_DEFAULT_NAME}}". Choose Start log. From that moment every line received is written to the file, until you choose Stop log or disconnect. More in Logging.

Levels and colours

{{const:APP_NAME}} gives every line a level, so that problems stand out and can be shown on their own.

LevelA line gets it when it contains
Critical{{const:SEVERITY_KEYWORDS.CRITICAL}}
Error{{const:SEVERITY_KEYWORDS.ERROR}}
Warning{{const:SEVERITY_KEYWORDS.WARNING}}
Info{{const:SEVERITY_KEYWORDS.INFO}}
Debug{{const:SEVERITY_KEYWORDS.DEBUG}}
CommandLines you sent, shown with {{const:COMMAND_PREFIX}} in front.
DataEverything else.

How a level is decided:

  1. A level the firmware prints is trusted first. ESP-IDF lines such as E (1234) wifi: ..., Zephyr lines such as <err> net: ... and bracketed levels such as [ERROR] ... or [WARN] ... are recognised exactly. So [INFO] error count: 0 is Info, not Error.
  2. Otherwise the words in the table are looked for, in any letter case, at the start of a word. "fail" matches "failed"; "fault" does not match inside "default". If several match, the most severe wins.

The level only chooses a colour and feeds the level buttons. It never decides whether a line is logged, exported or plotted.

The level buttons above the console show All, Error (errors and critical lines), Warning, Info, Debug and Data (data and the commands you sent). Each shows how many lines it holds. In a narrow window they become one drop-down.

To show every line alike, turn off Colour lines by severity on the Console page of Preferences.

Highlight rules

To make the lines you are watching for stand out, add a rule on the Highlights page of Preferences: a text to look for and a colour. A line that holds the text, whatever its case, is drawn in that colour, with a mark beside it in the margin. The first rule a line matches decides its colour. Up to {{const:HIGHLIGHT_RULES_MAX}} rules can be set. Highlights are on screen only: logs and exports keep every line as received.

ANSI colours

Some firmware colours its text with ANSI codes. These codes are always removed from the text that is shown, logged and exported. Switch on ANSI colours on the Features page of Preferences to see the colours in the console: each of the 16 ANSI colours is drawn in a version made to be read on the theme's background, and colours chosen with the 256-colour or true-colour codes are shown as the nearest of the 16. Background colours, bold and underline are not shown. A highlight rule's colour comes before an ANSI colour.

Filter lines

Type in the Filter lines field, or press {{key:filter}}, to show only the lines that contain that text. Letter case is ignored. The filter and the level buttons work together.

A filter changes only what is shown. Lines that are hidden are still received, logged and exported. Press {{key:close_find}} to clear it.

Find

Press {{key:find}} to open Find. Every occurrence of the text is highlighted; letter case is ignored.

  • {{key:find_next}} goes to the next match, {{key:find_previous}} to the previous one.
  • {{key:close_find}} closes Find.

Find highlights and leaves every line in place; Filter hides the lines that do not match. Use Find to move through a log, and Filter to cut it down.

Lines that begin with [WireTrace] are {{const:APP_NAME}}'s own notes in the session: they are in the console, the log and exports. A problem, such as lines not recorded or a lost connection, is marked WRN; an event, such as a control line you set, a break sent or the board back, is marked INF. No filter hides them, and the level counts never include them.

Timestamps

Each line carries the time it arrived. The button above the console switches between three ways of showing it, also offered in View > Timestamps:

  • Time of day, to the millisecond.
  • Date and time, to the millisecond, exactly as the log writes it: for a session that runs past midnight, or to match a line with its log. This is the default.
  • Since previous line, which shows how long each line came after the one before it. Useful for timing.

This changes the screen, and what is copied from it, only. Log files always hold the full date and time.

Following new lines

While Following is on, the console stays on the newest line. Scroll up to read something and following stops by itself, so the text you are reading does not move. A button at the bottom right then counts the new lines; choose it, or choose Not following, to return to the newest line.

Text and HEX

Text shows what the device sends as lines of text. HEX shows the bytes themselves, laid out as hexdump -C lays them out: {{const:HEX_BYTES_PER_ROW}} bytes to a row, in groups of {{const:HEX_BYTES_PER_GROUP}}, after the row's position, and then the same bytes as characters between bars.

00000000  52 50 4D 3A 20 31 36 39  37 2C 20 43 75 72 72 65  |RPM: 1697, Curre|
00000010  6E 74 3A 20 31 2E 32 0D  0A                       |nt: 1.2..|

A row always holds {{const:HEX_BYTES_PER_ROW}} bytes, so a longer line of text carries on in the next row: above, the line RPM: 1697, Current: 1.2 takes two. A byte that is not a printable character, such as the carriage return (0D) and line feed (0A) that end the line, is shown as a dot. The position, the bars and those dots are drawn quieter than the bytes, so the bytes stand out. Use HEX for a binary protocol, or to see exactly which bytes end a line.

Copy and the console menu

Select text with the mouse. {{key:copy}} copies it with its timestamps; {{key:copy_messages}} copies the messages alone. {{key:select_all}} selects everything.

Right-click the console for the same commands, Clear console, and three that work on the selected text:

  • Show only lines with the selected text, which puts it in the filter.
  • Find the selected text.
  • Export selection..., which saves the selected lines to a text file.

Text size: {{key:text_larger}}, {{key:text_smaller}} and {{key:text_reset}}, from {{const:FONT_SIZE_MIN}} to {{const:FONT_SIZE_MAX}} pixels.

Send a command

Type in the field at the bottom and press Enter or choose Send. The command appears in the console with {{const:COMMAND_PREFIX}} in front, and in the log if one is running.

  • Line ending. The list beside the field sets what is sent after the command: None, LF, CR or CR LF. Most devices expect LF or CR LF. If a device does not react to a command, this is the first thing to check.
  • History. The arrow at the end of the field lists the commands sent in this session, up to {{const:COMMAND_HISTORY_LIMIT}}.

Saved commands

Commands you send often can be saved, up to {{const:SAVED_COMMANDS_MAX}} of them.

  • Saved > Save the command in the box saves what you have typed.
  • Choosing a saved command puts it in the field, where you can change it before sending. Nothing is sent until you press Enter.
  • The first {{const:SAVED_COMMAND_SHORTCUTS}} have shortcuts: {{key:saved_command_1}} for the first, and so on.
  • Edit saved commands... changes, removes and reorders them.

Saved commands are shared by every tab.

Logging

ToDo this

PausePause stops writing for a while. Lines are still received and shown; they are not in the file. Resume continues in the same file.

Find the filesFile > Open log folder, or Show in the message that appears when a log starts or stops. A new log is offered the folder of the log before it.

While a log runs, the status bar shows its file name, how long it has run and how large it is.

File names

A log is named from the name you gave, the port and the moment it started, so two logs never overwrite each other:

Bench_COM7_2026-03-14_09-30-00.txt

Spaces in the name become underscores, and characters a file name cannot hold are removed.

Long captures

A log that reaches {{const:LOG_SPLIT_DEFAULT_MB}} MB continues in a new file, so that a long capture stays easy to open. The first file keeps its name; the files after it end in a number:

Bench_COM7_2026-03-14_09-30-00.txt
Bench_COM7_2026-03-14_09-30-00_002.txt
Bench_COM7_2026-03-14_09-30-00_003.txt

A line is never cut in two, and each file has its own header. Change the size, or turn the limit off, under Maximum log file size in Preferences.

What a log file holds

A text log starts with a header: the name, the port, the baud rate, when it started, the system it was made on and any notes you entered. Then one line for every line received:

[2026-03-14 09:30:00.123] Temperature: 22.4, Humidity: 65.8
  • The file is plain text in UTF-8.
  • Lines end with LF unless you choose CR LF in Preferences.
  • Where logging was paused, or lines could not be written, the log says so at that place, so the file never hides a gap.

CSV files

Choose Text and CSV when you start a log to get a spreadsheet file beside the text file. {{const:APP_NAME}} looks at the lines to find columns:

The device sendsThe CSV file gets
Temperature: 22.4, Humidity: 65.8
or temp=22.4 hum=65.8
or {"temp": 22.4, "hum": 65.8}		One column for the time and one for each name: Timestamp,Temperature,Humidity
Anything elseTwo columns: Timestamp,Data
  • A device that prints start-up messages before its readings is still recognised once the readings begin. After {{const:CSV_DETECTION_GIVE_UP_LINES}} lines with no columns found, the two-column form is used.
  • When columns were found, lines that do not fit them are left out of the CSV file so that it stays a clean table. The text log always holds every line.
  • While Maximum log file size is on, a CSV file also continues in a new file after {{count:CSV_MAX_ROWS_PER_PART}} rows, so that a spreadsheet can open each one.
  • A value that a spreadsheet would run as a formula is written so that it is shown as text.

Export a session

You do not have to start a log in advance. {{const:APP_NAME}} records every session as it goes, and Export ({{key:export}}) saves it afterwards as Text, CSV or both.

  • An export holds everything received since you connected, or since you last cleared the console.
  • It holds every line, including lines the console has dropped from the screen and lines hidden by a filter.
  • It still works after you disconnect, or after the connection is lost.
  • The device keeps being read while the file is written.

A session is recorded up to {{size:SPOOL_MAX_BYTES}}. Beyond that the oldest part is let go. For a capture longer than that, start a log.

To save only some lines, select them and choose Export selection... from the console menu.

How your data is kept safe

  • Reading and writing do not wait for the screen. If a device sends faster than this computer can draw, the console skips ahead and says how many lines it did not show. Those lines are still in the session and in the log.
  • Lines reach the disk quickly. A received line is written within {{seconds:LOG_FLUSH_INTERVAL_MS}} second unless you change it in Preferences, and the file is regularly made safe on the storage device, which limits what a power cut can cost.
  • A disk problem does not end the log. If the file cannot be written, for example because a network drive went away, {{const:APP_NAME}} says so and keeps trying. Logging continues by itself when the file can be written again.
  • Losses are never silent. If lines could not be written, their number is shown, and the place is marked in the console and in the log.
  • Closing asks first. Closing a tab or the program while a log or an export is running asks before it stops them.

Open the plot

Choose Plot or press {{key:plot}}. The plot opens in a window of its own and draws the numbers in the lines as they arrive. Closing that window closes the plot; {{key:plot}} opens it again, where it last was for that port. To have the plot open under the console instead, switch off Where it opens on the Plot page of Preferences; drag the bar between the console and the plot to give either more room.

To close it, choose the cross at the right end of the plot's toolbar, choose Plot again, or press {{key:plot}} again. While the plot is closed, no values are read from the lines; the console and the log carry on as before. Open it again and it carries on from the most recent lines.

The plot draws nothing until it has found numbers. A plot opened late starts from the most recent {{const:PLOT_RECENT_LINES_BUFFER_SIZE}} lines, so it does not have to wait for new ones.

How values are found

With no set-up, three ways of writing numbers are recognised:

FormExampleNames of the values

Marking the lines to plot

If a device prints both messages and readings, begin the reading lines with plt:. When the plot looks for numbers and finds such a line among the lines it looks at, it plots only the lines that begin with plt:.

plt: 22.4,55,1013

To name values that are sent without names, have the device print a line that begins with plt! and lists the names, before its readings:

plt! Temperature,Humidity,Pressure

The names are used when there are as many of them as there are values in a line.

If nothing is found

The plot looks for numbers once it has collected {{const:PLOT_AUTODETECT_SAMPLE_SIZE}} lines. After {{const:PLOT_DETECTION_GIVE_UP_LINES}} lines with no numbers recognised, the plot says so and offers Describe the format..., which opens Configure plot.

While the plot is live, scroll over a chart to show less or more recent time: the plot keeps following the newest data, and Time shown says Custom until you choose from it again. Every panel moves together, and each panel's scale always fits the values in the time shown. Fit undoes the zoom and, after a drag, returns to the live view.

Point at a chart to read it. A line marks the sample nearest the pointer, a dot marks each value there, and a card beside the line gives the time the sample was received (as the console writes it), its time on the chart in seconds, and each value shown at that moment. A value given at a moment is the last one received at or before it; a dash means none had been received yet.

Each tab has its own plot. The time along the bottom is in seconds, counted from the first line received in the session (or after Clear). It is taken from the arrival time of each line, the time the console and the log show.

Older time

The plot reaches back to the start of the session, as far as the session recording still holds; the start of a very long session may no longer be there, and the plot then says so.

While the plot is live, older time is drawn by the least and greatest value of each moment, so no spike is lost however far you zoom out; a note above the chart says so, and the figures beside each value show its latest value only. Pause or Measure, and the time shown is drawn in full detail, with exact figures beside each value. Where a single value cannot be shown, the card under the pointer and the measuring table say zoom in.

Measure

Measure puts two cursors, A and B, on the plot. Use it to time an event or to read a drop or a rise.

  • Measuring holds the plot still, so the cursors stay on what you are measuring. Values keep being collected; Resume goes back to live and ends measuring.
  • Drag A or B, or click a chart to move the nearer cursor there. A cursor always stops on a sample, never between two.
  • The table under the plot has a row for A, a row for B, and a row for B minus A. For A and B it gives the time each sample was received and each value then; in the last row, the time between them in seconds and how much each value changed. Under the console, the table takes its room from the console, so the chart keeps its height. In its own window, the window keeps the size you gave it and the table takes its room from the chart.

Choose Measure again to remove the cursors. A plot that measuring held goes back to live.

Configure plot

Open it with View > Configure plot... or Configure... in the plot's toolbar. You need it only when the values are not found by themselves.

  • Auto-detect is the behaviour described above.
  • Manual lets you describe the line with a pattern (a regular expression). Each named group becomes a value: RPM:\s*(?P<RPM>\d+) gives a value named RPM.

You do not have to write the pattern yourself:

  1. Select a line under Recent lines from this session.
  2. Choose Capture from sample..., click each number you want and give it a name.
  3. Choose Use this pattern. Below the list, the result says how many of the recent lines match and what was read from the first. Test pattern checks again after a change.
  4. Choose Apply.

A pattern that takes longer than {{const:PLOT_REGEX_TIMEOUT_SECONDS}} seconds on a line cannot be applied, so that a faulty pattern cannot slow the program down.

Profiles

Save as... keeps a pattern under a name, so you can use it again. A port remembers the profile it last used. The profile for a port that has none yet is set in Preferences.

Restarts and the session report

When a board restarts, it says so in the lines it prints as it starts. {{const:APP_NAME}} recognises two of these and adds a notice after the line, such as [WireTrace] Board restart 2 of this session: POWERON_RESET, to the console, the log and any export:

  • ESP32 (every chip of the family): the line the boot ROM prints at each reset, such as rst:0x1 (POWERON_RESET),boot:0x13 (SPI_FAST_FLASH_BOOT). The name in brackets is the reason the chip gives.
  • Zephyr: the boot banner each image prints as it starts, *** Booting Zephyr OS ..., or *** Using Zephyr OS ... with the nRF Connect SDK.

With a bootloader built on Zephyr whose own log is switched off, each restart is counted twice. Restart detection can be switched off on the Features page of Preferences.

Choose Device > Session report... for the report of the session in front, while it runs or after it ends: the port and its settings, when it was connected and how the connection ended, the running time, the lines received, the errors and warnings among them, the lines that could not be recorded because the disk could not keep up, each time the connection was lost and waited for, with how long the board was away, and each restart with its time and reason. The figures are exact, even when the screen skipped lines. Copy puts the report on the clipboard; Save... writes it to a text file.

Alerts

Switch on Alerts on the Features page of Preferences, and choose on the Alerts page what to be told about. Each tab alerts on its own board:

  • Error lines: a banner says how many lines at the Error or Critical level arrived, and quotes the latest. It keeps counting until you dismiss it. The count is exact, even when the screen skipped lines. Like an alarm, it reminds you while error lines keep arriving, at most once every Time between alerts, until you dismiss the banner. Dismissing it acknowledges them: lines that go on arriving only count on the banner, silently. Once none has arrived for the Time between alerts, the next one alerts again.
  • Connection lost: the tab already says so; the alert makes sure you notice.
  • Quiet board: while connected, when no line arrives for the time you set. The banner goes by itself once lines arrive again.

When a tab other than the one in front alerts, its dot on the tab bar is filled in the warning colour, and its tooltip says New alert, until you open it.

An alert also flashes the window's button in the taskbar (or its icon in the dock) while you are working in another window. If you chose Sound, it plays your system's own sound: on Windows the Notification sound of your sound scheme, elsewhere the system's alert sound. It follows your system's sound settings, so a computer set to play no sounds stays silent. Choosing Sound in Preferences plays it once, so you know what to listen for.

With Desktop notification chosen, an alert also shows a notification while you are working in another application, and WireTrace shows its icon in the notification area while this is on. The notification names the tab and what happened, never the text of a line, as it can show on a locked screen. Clicking it brings WireTrace forward at that tab. On Windows the notification plays the Notification sound itself, so you hear it once. Desktop notifications are not yet available on macOS, nor on a Linux desktop without a notification area.

However many tabs alert, sounds and notifications are paced. Alerts that arrive together, such as boards lost when a hub is unplugged, give one sound and one notification. After that, nothing more sounds or notifies for the Time between alerts ({{const:ALERT_PAUSE_SECONDS_DEFAULT}} seconds by default). Anything that happens meanwhile comes together in one alert when that time ends. The banners in the tabs always show at once.

Device > Alerts switches alerts on or off for the tab in front only, whatever the Features page says. Each tab follows Preferences until it is switched this way.

Tabs

  • {{key:new_tab}} opens a tab, {{key:close_tab}} closes it.
  • Each tab has its own connection, console, log, plot, filter and line ending. Tabs do not affect each other.
  • A port that is open in one tab is shown as in use in the others.
  • {{key:rename_tab}}, or a double-click on the tab, gives it a name of your own, such as "Motor controller". Enter keeps the name, Esc leaves it as it was.

What each port remembers

For every port you have connected to, {{const:APP_NAME}} remembers the baud rate and line settings, the line ending for commands, the plot profile, where its plot window was and the name of its tab, and offers them again the next time you choose that port. Up to {{const:PORT_MEMORY_LIMIT}} ports are remembered; beyond that, the one used longest ago is forgotten.

Connection lost

If a device is unplugged, resets its USB connection, or another program takes the port, {{const:APP_NAME}} says when it happened and waits for the same board to come back. The session goes on: the console keeps its lines, a running log stays open, and the plot keeps its values. Nothing received is lost.

When the board is back, the tab opens its port with the same settings and carries on, in the same log file. A notice in the console, the log and any export says when the connection was lost and when it came back, and how the board was recognised. Anything the board sent while it was disconnected could not be received, and the plot leaves a gap there rather than joining the lines across it. The session report lists each time.

A board is taken back only when it is recognised as the same one:

  • By serial number: a board whose USB adapter has a serial number of its own is recognised in any USB socket, under any port name. Some adapters share one serial number; when two connected adapters do, the board is recognised by its USB socket instead, or the tab asks.
  • By USB port: a board without a serial number is recognised when it comes back in the same USB socket, through the same hubs.
  • By port name: a port with no USB identity at all, such as a built-in COM port, a PCI card or a Bluetooth serial port, has only its name to go by. This can be switched off in Preferences.

If a board of the same model appears somewhere else and {{const:APP_NAME}} cannot tell whether it is yours, the tab asks. Reconnect takes it; Not this board keeps waiting and does not ask about that port again. A board another tab is connected to is never offered.

Stop waiting, or Disconnect, ends the session as if the board had not come back. The tab can also stop waiting by itself after the time set in Preferences. For a tab that should end its session at once when the connection is lost, switch off Device > Reconnect lost board while it is in front. Each tab follows Preferences until it is switched this way.

When a session ends because its board was lost, the tab says so in a bar:

  • Connect again opens the same port with the same settings.
  • Export session saves what was received.
  • Open log folder is offered when a log was running.

Troubleshooting

The port is not in the list

  • Press {{key:refresh_ports}}, and check the cable. Some USB cables carry power only.
  • The device may need a driver for its USB chip. The maker of the board says which.
  • On Linux, your user account may not be allowed to open serial ports. On many systems that is granted by membership of the dialout group (on some, uucp), followed by logging out and in again.

The port cannot be opened

Another program is probably using it: another serial monitor, or the tool that loads firmware onto the device. Only one program can hold a serial port. Close the other program and choose Connect again.

The text is unreadable

The baud rate does not match the device. Disconnect, choose the rate the device uses and connect again. If the device sends a binary protocol and not text, switch to HEX.

The device does not react to commands

Check the line ending beside the command field. Many devices act only when a command ends with LF or with CR LF.

The console says it is skipping lines

The device sends faster than this computer can draw. Every line is still recorded and logged; use the log or an export to see them all. Closing the plot, or raising Screen refresh in the Advanced page of Preferences, eases a slow computer.

The plot stays empty

No numbers were recognised in the lines. Check the forms in How values are found, or describe the line in Configure plot.

The CSV file has only two columns

No names and values were found in the first {{const:CSV_DETECTION_GIVE_UP_LINES}} lines, so each line was written whole. The CSV file needs lines such as name: value, name=value or JSON. Values with no names can be plotted but have no column names for a table.

A new version does not suit you

Return to the version you had: see Return to the previous version.

A new version does not start

Every earlier version stays on the release page, {{const:RELEASES_URL}}. Download the one you had and install it as you installed {{const:APP_NAME}}; it reads your settings as they are. Please report the problem, with the files of the diagnostic logs folder (see Folders).

Start again with the original settings

File > Preferences..., then Restore defaults. It takes effect at once and cannot be undone. Your plot profiles, highlight rules, saved commands, what each port remembers, and your choices about updates and usage statistics are kept.

Updates

{{const:APP_NAME}} looks for a new version shortly after it starts and every {{const:UPDATE_CHECK_INTERVAL_HOURS}} hours while it stays open. You can turn this off in Preferences, under Updates and privacy. Help > Check for updates... checks at once, whatever that setting.

A new version is announced by a message, and a button at the right of the status bar, Update to and the version, stays until you decide; your work is not interrupted. The button, or Help > Update to ..., opens the update window: what changed, the size of the download, and the choice to update now, be reminded in {{const:UPDATE_SNOOZE_HOURS}} hours, or skip that version. A skipped version is still offered in the Help menu. Nothing is installed without your choice.

If the automatic checks have failed for {{const:UPDATE_CHECKS_FAILING_DAYS}} days running, the status bar says since when updates have not been checked, with Check now; it goes once a check is answered. If a check or a download fails, a message says what happened and what to do, with Open the release page, where every version can be downloaded.

An update is accepted only if its description is signed by the maintainer of {{const:APP_NAME}}, and the download is used only if it is exactly the file that description names. A description that is not signed, or a file that differs, is refused.

Return to the previous version

If a new version does not suit you, Help > Return to version ... installs the version you had before. The entry names that version once {{const:APP_NAME}} knows it; until then it reads Return to the previous version... and looks the version up when you choose it. A window then says what will happen, and nothing starts until you choose Return to and the version.

  • The earlier version is downloaded and checked exactly as an update is: only a release the maintainer has signed is installed.
  • When an update is installed, {{const:APP_NAME}} first keeps a copy of your settings, named for the version they came from; the copies of the last {{const:SETTINGS_COPIES_KEPT}} versions are kept (see Folders). A return puts that version's copy back. Your saved commands, plot profiles, highlight rules and remembered ports stay as they are now, and so do your choices about updates and usage statistics. Without a copy for that version, for example after installing a version by hand, your settings stay as they are.
  • Open connections and logs are closed, as when {{const:APP_NAME}} exits. Logs already written are kept.
  • The earlier version offers the newest one again. Skip this version in its update window stops that.
