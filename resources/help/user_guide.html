{{const:APP_NAME}} user guide

For version {{const:APP_VERSION}}. Press {{key:user_guide}} in {{const:APP_NAME}} to open this page at any time.

What it does

{{const:APP_NAME}} shows what a device sends over a serial port, line by line, with the time each line arrived. It can write those lines to a log file, plot the numbers in them, send commands back, and do all of this for several devices at once, each in its own tab.

  • Lines are recorded as they arrive, whether or not the screen keeps up with a fast device.
  • Logs are plain text files that any editor opens. A spreadsheet file can be written beside them.
  • What your devices send never leaves your computer. See Privacy.

Connect a device

A new tab opens on the list of serial ports. The list updates by itself: plug a device in and it appears, marked New.

  1. Choose the port. Double-click it, or select it and press Enter, to connect at once.
  2. Check the baud rate. The list offers {{const:BAUD_RATES}}; you can also type any whole number from {{count:BAUD_RATE_MIN}} to {{count:BAUD_RATE_MAX}}. It must match the rate the device uses.
  3. Choose Connect.

Every connection uses 8 data bits, no parity and 1 stop bit (8N1), with no flow control.

A port you have used before is offered the baud rate it last used. A port used for the first time is offered {{const:DEFAULT_BAUD_RATE}}, or the rate you set in Preferences.

If the port does not appear, press {{key:refresh_ports}} and see Troubleshooting.

Start a log

The console shows the data; a log keeps it. Choose Start log or press {{key:start_log}}.

Give the log a name, or leave the field empty to use "{{const:FILENAME_DEFAULT_NAME}}". Choose Start log. From that moment every line received is written to the file, until you choose Stop log or disconnect. More in Logging.

Levels and colours

{{const:APP_NAME}} gives every line a level, so that problems stand out and can be shown on their own.

LevelA line gets it when it contains
Critical{{const:SEVERITY_KEYWORDS.CRITICAL}}
Error{{const:SEVERITY_KEYWORDS.ERROR}}
Warning{{const:SEVERITY_KEYWORDS.WARNING}}
Info{{const:SEVERITY_KEYWORDS.INFO}}
Debug{{const:SEVERITY_KEYWORDS.DEBUG}}
CommandLines you sent, shown with {{const:COMMAND_PREFIX}} in front.
DataEverything else.

How a level is decided:

  1. A level the firmware prints is trusted first. ESP-IDF lines such as E (1234) wifi: ..., Zephyr lines such as <err> net: ... and bracketed levels such as [ERROR] ... or [WARN] ... are recognised exactly. So [INFO] error count: 0 is Info, not Error.
  2. Otherwise the words in the table are looked for, in any letter case, at the start of a word. "fail" matches "failed"; "fault" does not match inside "default". If several match, the most severe wins.

The level only chooses a colour and feeds the level buttons. It never decides whether a line is logged, exported or plotted.

The level buttons above the console show All, Error (errors and critical lines), Warning, Info, Debug and Data (data and the commands you sent). Each shows how many lines it holds. In a narrow window they become one drop-down.

To show every line alike, turn off Colour lines by severity on the Console page of Preferences.

Filter lines

Type in the Filter lines field, or press {{key:filter}}, to show only the lines that contain that text. Letter case is ignored. The filter and the level buttons work together.

A filter changes only what is shown. Lines that are hidden are still received, logged and exported. Press {{key:close_find}} to clear it.

Find

Press {{key:find}} to open Find. Every occurrence of the text is highlighted; letter case is ignored.

  • {{key:find_next}} goes to the next match, {{key:find_previous}} to the previous one.
  • {{key:close_find}} closes Find.

Find highlights and leaves every line in place; Filter hides the lines that do not match. Use Find to move through a log, and Filter to cut it down.

Timestamps

Each line carries the time it arrived. The button above the console switches between two ways of showing it:

  • Time of day, to the millisecond.
  • Since previous line, which shows how long each line came after the one before it. Useful for timing.

This changes the screen only. Log files always hold the full date and time.

Following new lines

While Following is on, the console stays on the newest line. Scroll up to read something and following stops by itself, so the text you are reading does not move. A button at the bottom right then counts the new lines; choose it, or choose Not following, to return to the newest line.

Text and HEX

Text shows what the device sends as lines of text. HEX shows the bytes themselves, laid out as hexdump -C lays them out: {{const:HEX_BYTES_PER_ROW}} bytes to a row, in groups of {{const:HEX_BYTES_PER_GROUP}}, after the row's position, and then the same bytes as characters between bars.

00000000  52 50 4D 3A 20 31 36 39  37 2C 20 43 75 72 72 65  |RPM: 1697, Curre|
00000010  6E 74 3A 20 31 2E 32 0D  0A                       |nt: 1.2..|

A row always holds {{const:HEX_BYTES_PER_ROW}} bytes, so a longer line of text carries on in the next row: above, the line RPM: 1697, Current: 1.2 takes two. A byte that is not a printable character, such as the carriage return (0D) and line feed (0A) that end the line, is shown as a dot. The position, the bars and those dots are drawn quieter than the bytes, so the bytes stand out. Use HEX for a binary protocol, or to see exactly which bytes end a line.

Copy and the console menu

Select text with the mouse. {{key:copy}} copies it with its timestamps; {{key:copy_messages}} copies the messages alone. {{key:select_all}} selects everything.

Right-click the console for the same commands, Clear console, and three that work on the selected text:

  • Show only lines with the selected text, which puts it in the filter.
  • Find the selected text.
  • Export selection..., which saves the selected lines to a text file.

Text size: {{key:text_larger}}, {{key:text_smaller}} and {{key:text_reset}}, from {{const:FONT_SIZE_MIN}} to {{const:FONT_SIZE_MAX}} pixels.

Send a command

Type in the field at the bottom and press Enter or choose Send. The command appears in the console with {{const:COMMAND_PREFIX}} in front, and in the log if one is running.

  • Line ending. The list beside the field sets what is sent after the command: None, LF, CR or CR LF. Most devices expect LF or CR LF. If a device does not react to a command, this is the first thing to check.
  • History. The arrow at the end of the field lists the commands sent in this session, up to {{const:COMMAND_HISTORY_LIMIT}}.

Saved commands

Commands you send often can be saved, up to {{const:SAVED_COMMANDS_MAX}} of them.

  • Saved > Save the command in the box saves what you have typed.
  • Choosing a saved command puts it in the field, where you can change it before sending. Nothing is sent until you press Enter.
  • The first {{const:SAVED_COMMAND_SHORTCUTS}} have shortcuts: {{key:saved_command_1}} for the first, and so on.
  • Edit saved commands... changes, removes and reorders them.

Saved commands are shared by every tab.

Logging

ToDo this

PausePause stops writing for a while. Lines are still received and shown; they are not in the file. Resume continues in the same file.

Find the filesFile > Open log folder, or Show in the message that appears when a log starts or stops. A new log is offered the folder of the log before it.

While a log runs, the status bar shows its file name, how long it has run and how large it is.

File names

A log is named from the name you gave, the port and the moment it started, so two logs never overwrite each other:

Bench_COM7_2026-03-14_09-30-00.txt

Spaces in the name become underscores, and characters a file name cannot hold are removed.

Long captures

A log that reaches {{const:LOG_SPLIT_DEFAULT_MB}} MB continues in a new file, so that a long capture stays easy to open. The first file keeps its name; the files after it end in a number:

Bench_COM7_2026-03-14_09-30-00.txt
Bench_COM7_2026-03-14_09-30-00_002.txt
Bench_COM7_2026-03-14_09-30-00_003.txt

A line is never cut in two, and each file has its own header. Change the size, or turn the limit off, under Maximum log file size in Preferences.

What a log file holds

A text log starts with a header: the name, the port, the baud rate, when it started, the system it was made on and any notes you entered. Then one line for every line received:

[2026-03-14 09:30:00.123] Temperature: 22.4, Humidity: 65.8
  • The file is plain text in UTF-8.
  • Lines end with LF unless you choose CR LF in Preferences.
  • Where logging was paused, or lines could not be written, the log says so at that place, so the file never hides a gap.

CSV files

Choose Text and CSV when you start a log to get a spreadsheet file beside the text file. {{const:APP_NAME}} looks at the lines to find columns:

The device sendsThe CSV file gets
Temperature: 22.4, Humidity: 65.8
or temp=22.4 hum=65.8
or {"temp": 22.4, "hum": 65.8}		One column for the time and one for each name: Timestamp,Temperature,Humidity
Anything elseTwo columns: Timestamp,Data
  • A device that prints start-up messages before its readings is still recognised once the readings begin. After {{const:CSV_DETECTION_GIVE_UP_LINES}} lines with no columns found, the two-column form is used.
  • When columns were found, lines that do not fit them are left out of the CSV file so that it stays a clean table. The text log always holds every line.
  • While Maximum log file size is on, a CSV file also continues in a new file after {{count:CSV_MAX_ROWS_PER_PART}} rows, so that a spreadsheet can open each one.
  • A value that a spreadsheet would run as a formula is written so that it is shown as text.

Export a session

You do not have to start a log in advance. {{const:APP_NAME}} records every session as it goes, and Export ({{key:export}}) saves it afterwards as Text, CSV or both.

  • An export holds everything received since you connected, or since you last cleared the console.
  • It holds every line, including lines the console has dropped from the screen and lines hidden by a filter.
  • It still works after you disconnect, or after the connection is lost.
  • The device keeps being read while the file is written.

A session is recorded up to {{size:SPOOL_MAX_BYTES}}. Beyond that the oldest part is let go. For a capture longer than that, start a log.

To save only some lines, select them and choose Export selection... from the console menu.

How your data is kept safe

  • Reading and writing do not wait for the screen. If a device sends faster than this computer can draw, the console skips ahead and says how many lines it did not show. Those lines are still in the session and in the log.
  • Lines reach the disk quickly. Unless you change it in Preferences, a received line waits in memory for at most {{seconds:LOG_FLUSH_INTERVAL_MS}} second before it is written, and every {{seconds:LOG_FSYNC_INTERVAL_MS}} seconds the system is told to put the file on the storage device, which limits what a power cut can cost.
  • A disk problem does not end the log. If the file cannot be written, for example because a network drive went away, {{const:APP_NAME}} says so and keeps trying. Logging continues by itself when the file can be written again.
  • Losses are never silent. If lines could not be written, their number is shown, and the place is marked in the console and in the log.
  • Closing asks first. Closing a tab or the program while a log or an export is running asks before it stops them.

Open the plot

Choose Plot or press {{key:plot}}. The plot opens under the console and draws the numbers in the lines as they arrive. Drag the bar between the console and the plot to give either more room.

To close it, choose the cross at the right end of the plot's toolbar, choose Plot again, or press {{key:plot}} again. While the plot is closed, no values are read from the lines; the console and the log carry on as before. Open it again and it carries on from the most recent lines.

The plot draws nothing until it has found numbers. A plot opened late starts from the most recent {{const:PLOT_RECENT_LINES_BUFFER_SIZE}} lines, so it does not have to wait for new ones.

Marking the lines to plot

If a device prints both messages and readings, begin the reading lines with plt:. When the plot looks for numbers and finds such a line among the lines it looks at, it plots only the lines that begin with plt:.

plt: 22.4,55,1013

To name values that are sent without names, have the device print a line that begins with plt! and lists the names, before its readings:

plt! Temperature,Humidity,Pressure

The names are used when there are as many of them as there are values in a line.

If nothing is found

The plot looks for numbers once it has collected {{const:PLOT_AUTODETECT_SAMPLE_SIZE}} lines. After {{const:PLOT_DETECTION_GIVE_UP_LINES}} lines with no numbers recognised, the plot says so and offers Describe the format..., which opens Configure plot.

Measure

Measure puts two cursors, A and B, on the plot. Use it to time an event or to read a drop or a rise.

  • Measuring holds the plot still, so the cursors stay on what you are measuring. Values keep being collected; Resume goes back to live and ends measuring.
  • Drag A or B, or click a chart to move the nearer cursor there. A cursor always stops on a sample, never between two.
  • The table under the plot has a row for A, a row for B, and a row for B minus A. For A and B it gives the time each sample was received and each value then; in the last row, the time between them in seconds and how much each value changed. The table takes its room from the console (or, with the plot in its own window, makes the window taller), so the chart keeps its height.

Choose Measure again to remove the cursors. A plot that measuring held goes back to live.

Configure plot

Open it with View > Configure plot... or Configure... in the plot's toolbar. You need it only when the values are not found by themselves.

  • Auto-detect is the behaviour described above.
  • Manual lets you describe the line with a pattern (a regular expression). Each named group becomes a value: RPM:\s*(?P<RPM>\d+) gives a value named RPM.

You do not have to write the pattern yourself:

  1. Select a line under Recent lines from this session.
  2. Choose Capture from sample..., click each number you want and give it a name.
  3. Choose Use this pattern. Below the list, the result says how many of the recent lines match and what was read from the first. Test pattern checks again after a change.
  4. Choose Apply.

A pattern that takes longer than {{const:PLOT_REGEX_TIMEOUT_SECONDS}} seconds on a line cannot be applied, so that a faulty pattern cannot slow the program down.

Profiles

Save as... keeps a pattern under a name, so you can use it again. A port remembers the profile it last used. The profile for a port that has none yet is set in Preferences.

Tabs

  • {{key:new_tab}} opens a tab, {{key:close_tab}} closes it.
  • Each tab has its own connection, console, log, plot, filter and line ending. Tabs do not affect each other.
  • A port that is open in one tab is shown as in use in the others.
  • {{key:rename_tab}}, or a double-click on the tab, gives it a name of your own, such as "Motor controller". Enter keeps the name, Esc leaves it as it was.

What each port remembers

For every port you have connected to, {{const:APP_NAME}} remembers the baud rate, the line ending for commands, the plot profile and the name of its tab, and offers them again the next time you choose that port. Up to {{const:PORT_MEMORY_LIMIT}} ports are remembered; beyond that, the one used longest ago is forgotten.

Connection lost

If a device is unplugged, or another program takes the port, {{const:APP_NAME}} says when it happened. Nothing received is lost: the console keeps its lines and a running log is closed properly.

  • Connect again opens the same port with the same settings.
  • Export session saves what was received.
  • Open log folder is offered when a log was running.

Troubleshooting

The port is not in the list

  • Press {{key:refresh_ports}}, and check the cable. Some USB cables carry power only.
  • The device may need a driver for its USB chip. The maker of the board says which.
  • On Linux, your user account may not be allowed to open serial ports. On many systems that is granted by membership of the dialout group (on some, uucp), followed by logging out and in again.

The port cannot be opened

Another program is probably using it: another serial monitor, or the tool that loads firmware onto the device. Only one program can hold a serial port. Close the other program and choose Connect again.

The text is unreadable

The baud rate does not match the device. Disconnect, choose the rate the device uses and connect again. If the device sends a binary protocol and not text, switch to HEX.

The device does not react to commands

Check the line ending beside the command field. Many devices act only when a command ends with LF or with CR LF.

The console says it is skipping lines

The device sends faster than this computer can draw. Every line is still recorded and logged; use the log or an export to see them all. Closing the plot, or raising Screen refresh in the Advanced page of Preferences, eases a slow computer.

The plot stays empty

No numbers were recognised in the lines. Check the forms in How values are found, or describe the line in Configure plot.

The CSV file has only two columns

No names and values were found in the first {{const:CSV_DETECTION_GIVE_UP_LINES}} lines, so each line was written whole. The CSV file needs lines such as name: value, name=value or JSON. Values with no names can be plotted but have no column names for a table.

Start again with the original settings

File > Preferences..., then Restore defaults. It takes effect at once and cannot be undone. Your plot profiles, saved commands, what each port remembers and the update check setting are kept.

Updates

{{const:APP_NAME}} looks for a new version shortly after it starts and every {{const:UPDATE_CHECK_INTERVAL_HOURS}} hours while it stays open. You can turn this off in Preferences, under Updates and privacy. Help > Check for updates... checks at once, whatever that setting.

A new version is announced by a message; your work is not interrupted. Open it to see what changed, and decide: update now, be reminded in {{const:UPDATE_SNOOZE_HOURS}} hours, or skip that version. Nothing is installed without your choice.

An update is accepted only if its description is signed by the maintainer of {{const:APP_NAME}}, and the download is used only if it is exactly the file that description names. A description that is not signed, or a file that differs, is refused.

Privacy

  • What your devices send stays on your computer, in the files you choose to write.
  • Settings, saved commands and what each port remembers are kept in the settings file on your computer.
  • {{const:APP_NAME}} connects to the internet by itself only to check for a newer version, to send usage statistics if you choose to share them, and, after you switch them off, to ask the server to delete what was sent.
  • The update check states the version, the operating system, the processor type, how {{const:APP_NAME}} was installed and the date of the previous check. It carries no identifier. The file it reads is on the website, which GitHub Pages hosts, so GitHub also receives the request. You can turn it off in Preferences, under Updates and privacy.
  • Usage statistics are off unless you switch them on. {{const:APP_NAME}} asks once, with a bar above the tabs. If you share them, {{const:APP_NAME}} makes a random installation identifier and sends one report for each day it is used: the identifier and the date; which features were used; whether lines were lost, a log could not be written, a connection was lost or {{const:APP_NAME}} closed unexpectedly; the highest line rate, the number of connections, the longest time one window stayed open and the number of starts, as ranges; the theme; the display scale; and the same version and system details as the update check. A report never holds a port or device name, a file name, a command, or anything a device sent.
  • You can change your answer at any time in Preferences, under Updates and privacy. Switching statistics off deletes the identifier and everything kept for them on your computer, and asks the server to delete every report sent under that identifier.
  • The privacy policy is at {{const:APP_PRIVACY_URL}}.
