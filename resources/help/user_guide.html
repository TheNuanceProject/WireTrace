Getting Started

Overview

WireTrace is a professional serial data monitor for embedded and IoT engineers. It captures, classifies, plots, and exports serial data in real time, with no configuration required for most devices.

Capabilities at a glance:

  • Monitor multiple serial ports simultaneously, each in its own tab
  • Sustained throughput of 10,000+ lines per second per tab
  • Automatic severity classification across 7 tags (CRITICAL, ERROR, WARNING, INFO, DEBUG, COMMAND, DATA)
  • Live data plotter with auto-detected JSON / key:value / delimited formats
  • Manual plot configuration with named, persistent profiles
  • Buffered logging to .txt and .csv with automatic column detection
  • Real-time search and line filtering — disk log always remains complete
  • Studio Light and Midnight Dark themes
  • Cross-platform — Windows, macOS, and Linux

Your First Connection

  1. Connect your serial device (USB, FTDI, etc.) to the computer.
  2. Launch WireTrace. The welcome screen offers a single action: Connect a Device.
  3. Click it. A new tab opens with the connection panel.
  4. Select your port from the Port dropdown. Click Refresh if the device isn't listed.
  5. Pick the baud rate (default 115200). You can also type a custom rate directly.
  6. Click Connect.

Incoming data appears immediately in the console.

Tip The port dropdown shows the device description and manufacturer (e.g. "COM3 — Arduino Uno (Arduino LLC)") to help you pick the right one when several USB serial adapters are connected.

Your First Log

  1. Once connected, click Log On in the toolbar.
  2. The New Log dialog opens. Enter a session name (e.g. MotorTest).
  3. Choose a save directory and export format (.txt, .csv, or both).
  4. Optionally add a description.
  5. Click Start Logging. Every incoming line is now written to disk.
  6. Click Log Off to stop. WireTrace flushes buffers and closes the files cleanly.
Disk log is always complete Logging captures every line from the serial port. Console filters, search highlights, and display settings have no effect on what is written to disk. See Data Integrity for the buffering and durability guarantees.

Interface

Multi-Device Tabs

WireTrace supports multiple simultaneous serial connections. Each device runs in its own tab with completely isolated data, threads, log engines, and plot engines.

  • Click the + button (or Ctrl+T) to create a new tab.
  • Each tab maintains its own connection panel, console, log engine, plot engine, and status bar.
  • Closing a tab while logging is active prompts for confirmation, then performs an ordered shutdown: flush → finalise CSV → fsync → close → release the port.
  • Right-click a tab header to Rename or Close.
  • When all tabs close, the welcome screen returns.

Console Display

The console is a high-performance virtual viewport: only the visible lines are painted, so memory remains bounded regardless of total data volume. The complete log is always on disk.

  • Auto-scroll — enabled by default. New lines scroll into view as they arrive. Scrolling up manually pauses auto-scroll; scrolling back to the bottom re-enables it.
  • Color mode — messages are colour-coded by severity (see Message Classification).
  • Clear — clears the console display. Does not affect log files or the plot.

Live Plotter

Plot Overview

The Live Plotter renders incoming numeric data as time-series traces in real time. It opens in a panel below the console, with a draggable splitter between them.

To open the plot:

  • Click the Plot button on the toolbar, or
  • Choose View → Live Plot, or
  • Press Ctrl+Shift+P.

The plotter samples the first 50 DATA-tagged lines after connection and tries to detect numeric structure automatically. If detection succeeds, traces appear with a legend. If detection fails after 200 lines, the placeholder shows a Configure manually… button so you can declare your own regex (see Configure Plot).

Per-tab independence Each tab has its own plot engine and its own buffers. Toggling the plot panel on one tab does not affect any other tab. Profiles (described under Saving Profiles) are shared across tabs, since they live in your preferences.

Pause is not the same as Log Pause The plot's Pause button only freezes the plot's redraw. The serial reader, log engine, and CSV writer continue normally. To pause writing to disk, use Log Pause in the main toolbar.

Auto-Detect Formats

Auto-detect examines the first 50 DATA-tagged lines and matches them against three parsers, in order:

FormatExample lineDetected columns
JSON {"temp":25.3,"hum":60.1} temp, hum
Key:Value Temperature: 25.3, Humidity: 60.1 Temperature, Humidity
Delimited 25.3, 60.1, 1013.2 ch0, ch1, ch2

A column is accepted only if it appears in at least 70% of the matching sample lines. This threshold ignores boot banners and one-off debug spam that happen to look like KV pairs.

Only DATA-tagged lines are sampled. Severity and command lines reach the disk log but never pollute the plot's column detection.

Prefix Routing (plt:)

When your firmware emits mixed traffic and you want to plot only specific lines, prefix them with plt:. Other lines still appear in the console and the disk log but are excluded from the plot. 

plt: 25.3, 60.1, 1013.2
DEBUG: i2c transfer ok
plt: 25.4, 60.0, 1013.1

Numbered variants plt0:, plt1:, plt2: … are also accepted and route to the same plot. They are useful when your firmware classifies its output streams numerically (e.g. one task emits plt0: and another emits plt1:); both are plotted on the same axes under the same column structure.

To declare explicit column names with positional (delimited) data, emit a one-time configuration line: 

plt!Vbat,Iload,Tcase
plt: 3.71, 0.85, 42.1
plt: 3.70, 0.86, 42.2

Without the plt! line, positional columns are auto-named ch0, ch1, … The plt! line is consumed by the plotter and does not appear as a data point. The column count in plt! must match the count in the data lines — otherwise the names are ignored and auto-naming applies.

Legend & Trace Toggling

The legend lists each detected column with its trace colour. Click any legend entry's coloured sample to hide or show that trace — useful for inspecting one channel without recompiling firmware or re-launching.

Theme switches (Studio Light ↔ Midnight Dark) rebuild the legend so trace labels remain readable in either theme.

Configure Plot

When to Configure

Auto-detect works for most well-structured serial data, but real firmware often emits formats it cannot parse: timestamped prefixes, log-level prefixes, custom delimiters, embedded units. When you need precise control over what gets plotted, open Configure Plot.

Three ways to open it:

  • View → Configure Plot…
  • Configure… button on the plot toolbar
  • The Configure manually… button that appears in the plot placeholder when auto-detect gives up

Auto vs Manual Mode

ModeWhen to use
Auto-detect Default. Use this whenever your firmware emits JSON, key:value pairs, or simple delimited numbers.
Manual (regex) Use this when the auto-detect pipeline can't recognise your format. You declare a regex with named groups; each (?P<name>…) becomes a plot column.

Manual Regex

Manual mode uses Python's regular expression syntax with named groups. Each named group becomes one trace. Values must parse as floats — non-numeric captures cause that line to be rejected.

Example. For this firmware output:

[2026-05-24 14:30:01.123] RPM: 1461, Current: 3.31, Voltage: 12.20, MotorTemp: 49.7

A pattern that captures all four values:

RPM:\s*(?P<RPM>\d+),\s*Current:\s*(?P<Current>[\d.]+),\s*Voltage:\s*(?P<Voltage>[\d.]+),\s*MotorTemp:\s*(?P<MotorTemp>[\d.]+)

The pattern uses search semantics, not full-line match — surrounding text such as the timestamp prefix doesn't break the match. You only need to write the part you care about.

Use named groups Unnamed groups (e.g. (\d+)) are ignored. Every value you want to plot must be wrapped in (?P<name>…) where name is the trace label that will appear in the legend.

Capture from Sample

Writing regex by hand is optional. The Capture from sample… button opens an assistant that does it for you:

  1. Select a recent line from the list in the dialog.
  2. Click Capture from sample….
  3. The sample line opens in a sub-dialog with each numeric value highlighted as a yellow chip.
  4. Click each chip you want to plot. Give it a name (the dialog suggests one based on the surrounding text).
  5. Click Use this pattern.

The generated regex appears in the pattern field, ready to test or save.

Tiered Test Result

Clicking Test pattern runs your regex against the last 200 lines from the engine and shows one of three tiers:

TierMeaningApply enabled?
✓ Green Pattern compiled and matched at least one recent line. Columns and a preview are shown. Yes
⚠ Amber Pattern is structurally valid but didn't match any recent line. Useful if the firmware happens to be quiet right now — the pattern will still apply to new data. Yes
✗ Red Pattern is broken: compile error, no named groups, or empty. The error message is shown inline. No

Saving Profiles

Patterns can be saved as named profiles for reuse across sessions and devices. Inside the dialog:

  • Save As… — create a new profile with a name of your choice. The profile must be in a structurally valid state to save (Test result Green or Amber).
  • Rename — rename a user profile.
  • Delete — remove a user profile.

Profiles are stored in your preferences.ini and persist across application restarts. The exact location is listed under File Locations.

Built-in Auto-detect is protected The built-in Auto-detect profile cannot be renamed or deleted — the Rename and Delete buttons are disabled while it is selected.

Default Profile

The default profile is the one applied automatically when a new tab opens and when an existing tab reconnects. Change it in two places:

  • File → Preferences → Plot → Default profile for the persistent choice that survives application restarts.
  • Inside Configure Plot… at any time, by selecting a profile and clicking Apply. This affects the current tab only.

Press Ctrl+S to instantly save the console contents to a .txt file. No dialog appears — the file is auto-named and saved to your default log directory. A toast notification confirms the save.

CSV Modes

WireTrace detects the structure of your serial data and applies one of two CSV modes:

ModeDetectionOutput
Auto-detect Data contains key:value or key=value pairs, or JSON objects, in ≥70% of the first 50 DATA-tagged lines. Keys become column headers. Values are placed in the matching columns. Severity and command lines go to the .txt file only.
Raw Unstructured data (no consistent pattern detected). Two columns: Timestamp and Data.

Example structured output:

Timestamp,Temperature,Humidity,Pressure
2026-05-24 14:30:01.123,25.3,60.1,1013.2

Sampling excludes severity lines The 50-line CSV detection sample uses only DATA-tagged lines. Boot banners and warning messages reach the .txt log but cannot pollute the CSV schema.

File Naming

Log and export files follow a consistent convention:

{Name}_{Port}_{YYYY-MM-DD}_{HH-MM-SS}.{ext}

Examples:

SensorCalibration_COM7_2026-05-24_09-15-30.csv

Search & Filter

Search and Filter controls sit on the same row at the bottom of the console area. The filter is always visible; the search appears to its right when activated.

Search

Press Ctrl+F to activate the search field. Type a term to highlight all matching occurrences in the console.

  • F3 — jump to next match.
  • Shift+F3 — jump to previous match.
  • Escape — close search and clear highlights.
  • The match counter shows your position (e.g. 3/47).

The filter field is always visible. Type a term to hide all non-matching lines from the console in real time. Press Ctrl+L to focus the filter quickly.

Message Classification

WireTrace classifies incoming lines into 7 severity levels by keyword detection. Each tag is displayed with a distinct colour. Classification uses priority ordering — the most severe matching tag wins.

TagTrigger keywordsExample
CRITICAL fatal, critical, panic, crash CRITICAL: Watchdog reset — system halted
ERROR error, fail, exception, fault ERROR: I2C timeout on sensor 0x48
WARNING warn, warning, caution WARNING: Battery voltage below threshold
INFO info, connected, ready, success, ok, initialized, complete INFO: WiFi connected to AP
DEBUG debug, trace, verbose DEBUG: Buffer utilisation at 23%
COMMAND Lines sent from the command bar >>> AT+RST
DATA Everything else Temperature: 25.3°C
Word-boundary matching Keywords match at a left word boundary, so a keyword embedded inside another word does not trigger a match: "default" will not be misclassified as ERROR because fault is in the middle of the word. Common suffixes are matched by design — "failed", "failing", and "warnings" all classify correctly. Words that begin with a keyword (such as "information") will match the underlying tag; this is intentional, since suffix tolerance for "failed"/"warning"/"connected" is more useful in practice than strict whole-word matching.

Data Integrity

WireTrace's logging path is designed so that an unexpected termination (power cut, kernel panic, force-quit) loses only a bounded amount of recent data — not the entire session.

The buffering model:

  1. Incoming lines enter a collections.deque with a 50,000-line cap (automatic O(1) overflow protection).
  2. An OS-level 64 KB write buffer batches actual writes.
  3. Three flush triggers:
    • Buffer reaches 5,000 entries
    • 1-second flush timer fires
    • Log Off or tab close runs the final flush
  4. A 30-second fsync() timer additionally hands the OS buffer to disk hardware, so a power cut bounds worst-case loss to 30 seconds of in-flight data — not the entire session.
  5. On Log Off: flush → finalise CSV → fsync → close, in that order.
Worst-case loss is bounded to ~30 seconds In the absolute worst case — a power cut between two fsync cycles with the deque holding the maximum buffered data — you lose at most the last 30 seconds before the cut. Properly closing the log via Log Off guarantees zero loss.

Auto-Update

WireTrace checks for updates automatically on startup. When a new version is available, a dialog presents three options:

  • Update Now — downloads the installer with a live progress bar, verifies its integrity (SHA-256 hash from the signed update manifest at https://thenuanceproject.com), then prompts to install. Install & Restart launches the installer and closes WireTrace.
  • Remind Later — snoozes the notification for 24 hours.
  • Skip This Version — suppresses the notification for that specific version.

You can also check manually via Help → Check for Updates.

Troubleshooting

Port not listed

Click Refresh to re-scan. Confirm the device is plugged in and drivers are installed. On Linux, your user may need to be in the dialout group: sudo usermod -aG dialout $USER (then log out and back in).

Garbled or unreadable data

Almost always a baud rate mismatch. Confirm the correct rate in your device's documentation. Common rates: 9600, 38400, 57600, 115200, 230400.

Data appears to lag or stutter

At very high data rates (>5,000 lines/sec), make sure no other application is competing for the same serial port. Close any other serial monitors. WireTrace batches GUI updates at 50 ms intervals to keep the interface responsive while disk and plot pipelines stay fully real-time.

Log file appears empty mid-session

Log files are buffered for performance and visibility may lag the on-disk state by up to one second (flush interval) or 30 seconds (fsync interval). On Log Off, all buffers are flushed and the file becomes immediately visible at its full size. See Data Integrity.

CSV has only two columns

Your serial data was not detected as structured. Auto-detect requires consistent key:value, key=value, or JSON formatting in ≥70% of the first 50 DATA-tagged lines. If your firmware emits a mixed stream, consider prefixing data lines with plt: (the same prefix that controls plotting routing applies here) or switch to manual plot configuration to declare your format explicitly.

Plot stays empty even though console is scrolling

Auto-detect couldn't find numeric structure within 200 lines and has given up. The plot placeholder shows a Configure manually… button — click it to open the Configure Plot dialog and declare your format using the Capture from sample assistant or a hand-written regex.

Plot legend shows a trace but no line is visible

That trace's visibility was toggled off. Click the coloured sample to the left of its legend label to bring it back. The same click hides any trace you want to remove from view without affecting the underlying data.

Resetting preferences

If WireTrace behaves unexpectedly, you can reset all settings by deleting the preferences file (see File Locations) and restarting the application.

Deleting preferences also deletes saved plot profiles Saved plot profiles live inside preferences.ini. If you want to keep them, copy the [Plot] section out of the file before deleting, or back the entire file up first.
